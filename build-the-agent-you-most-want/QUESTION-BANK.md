# 提问银行

阶段 1 的弹药库。**不是清单，是取舍**：每组挑 1–2 个最切题的问，一次问 2–4 个。

用法：读完一轮回答后，**先找矛盾，再挑下一组**。矛盾的优先级永远高于"这组还没问过"。

---

## 一、边界组：定义"不做什么"

否定比肯定更能定义产品。用户说"什么都要"时，他其实还没想清楚。

| 问题 | 逼出什么 |
|---|---|
| 这个系统**绝不做**什么？ | 范围。没有否定的需求文档等于没有范围 |
| 哪些事你宁可手动做，也不想让它自动？ | 自动化的真实边界（往往和市场宣传的相反） |
| 如果只能保留一个功能，留哪个？ | 真实优先级，绕开"都很重要" |
| 这个工具**不该**被谁用？ | 用户画像的反面，常常比正面清晰 |

> 样本里，用户对"绝不做"的回答直接排除了两阶段交付方案 —— 那一条比任何"要做什么"都省时间。

---

## 二、反例组：逼出验收标准

**没有人能描述清楚自己要什么，但几乎所有人都能指出什么不对。** 反例组是把后者转成前者的唯一路径。

| 问题 | 逼出什么 |
|---|---|
| 什么情况下你会觉得**它做错了**？ | 隐含的验收标准 |
| 给我一个它**输出正确但你依然不满意**的例子 | 区分"对"和"有用"。这一条极难答，但答案最值钱 |
| 你会怎么判断这次的输出比上次好？ | 可度量的质量维度 |
| 最坏的情况下，它能错到什么程度？ | 失败容忍度 |

> 样本里用户对面试要点提的要求是"**只呈现事实，不要结论，结论我自己下**"。
> 这不是功能需求，是从"它做对了我也可能不满意"里逼出来的一条 ——
> 它最后变成了提示词里的一句铁律。

## 三、替代组：防止过度设计

| 问题 | 逼出什么 |
|---|---|
| 用一个脚本 / 一条命令能不能解决？ | 如果答案是"能"，那就不该上 agent |
| 不用 LLM 的那部分有哪些？ | 哪些步骤是确定性的，别交给概率模型 |
| 如果这个模型明天涨价 10 倍，你还做吗？ | 真实依赖度 |
| 有没有现成工具已经做了 80%？ | 避免重造轮子，也避免"重造"带来的维护成本 |

> **这一组最容易被跳过，也最该问。** 用户来找 agent 时通常已经假定"要用 LLM"，
> 而这个假定本身常常是错的。样本里的会议记录工具，**录音、切分、检索全是确定性的**，
> 只有"判类型"和"提炼要点"两处真的需要模型。

## 四、成本组：区分可逆与不可逆

| 问题 | 逼出什么 |
|---|---|
| 这个决定错了，**改回来的代价**是什么？ | 可逆性。可逆的决定快速试，不可逆的慢慢想 |
| 你愿意为这个功能等多久？ | 性能预算。3 小时音频跑 90 分钟能接受吗 |
| 你每周愿意花多少时间维护它？ | 复杂度上限。答案通常是"几乎为零"，那就别上需要运维的方案 |
| 硬件上限是多少？ | 把"本地跑"从愿望变成约束 |

> 样本里"有没有独显 / 显存多大 / 是哪一代 CPU"这三个答案**直接决定了技术选型**，
> 而它们是在成本组问出来的，不是用户主动说的。
>
> 追问硬件不是打听隐私 —— 它是把"想在本地跑"从愿望变成**可计算的约束**的唯一办法。

## 五、数据组：分歧几乎总在这里

| 问题 | 逼出什么 |
|---|---|
| 数据从哪来？ | 输入形态（实时流？文件？设备？） |
| 处理后到哪去？ | 存储策略、保留期限 |
| **谁能看见？** | 隐私等级。这一条决定了能不能用云服务 |
| 出本机的**最小必要集**是什么？ | 往往是"只要文字，不要音频"。找到它，就能把风险降到最低 |
| 删除时，要删几处？ | 样本里答案是四处：音频、逐字稿、产出、索引。少一处就是留尾巴 |

> **"最小必要集"是本组最有价值的问题。** 样本里它把"要么全本地、要么全上云"的
> 二选一，变成了"音频永不出、只出文字"的三档可控。

## 六、失败组：逼出"绝不静默"

| 问题 | 逼出什么 |
|---|---|
| 它挂了，**你怎么知道**？ | 可观测性需求 |
| 什么情况下它会**悄悄给出错误结果**？ | 最危险的失败模式 |
| 你能接受的最长无反馈时间是多久？ | 进度反馈的设计目标 |
| 跑到一半崩了，你希望它怎么办？ | 断点续跑 vs 从头再来 |
| 失败时宁可**给一半**还是**什么都不给**？ | 降级策略 |

> **"悄悄给出错误结果"是这组里最该问的。** 崩溃会被发现，静默的错误不会。
> 样本里由此推出一条贯穿全系统的原则：**任何一步失败都记进 `errors` 并标 partial，
> 绝不硬编一个模板继续往下走** —— 那等于编造。
>
> 这条原则后来落成了 [`LANDING.md`](LANDING.md) 的「绝不静默」一节。

## 反问句的三种变形

同一个问题，换个问法得到的答案深度完全不同：

| 弱 | 中 | 强 |
|---|---|---|
| 你想要什么功能？ | 这个功能解决什么问题？ | 如果不做这个功能，你会怎么办？ |
| 这个重要吗？ | 它和 X 哪个更重要？ | 如果必须砍掉一个，你砍哪个？ |
| 数据敏感吗？ | 数据能出本机吗？ | 数据出本机后，最坏会发生什么？ |

**规律**：把"是/否"问题改成"**取舍**"问题，把"取舍"问题改成"**后果**"问题。
每往右一列，用户就多想一层。

## 什么时候该停止提问

出现下面任一信号，进阶段 2：

- 新问题开始得到**重复答案**（认知地图画完了）
- 用户的回答里开始出现**具体的数字**（他已经在算成本了，说明想清楚了）
- 用户开始**反问你怎么做**（他在等你给方案了）
- 你已经问了 3 轮，且最近一轮没有出现新的矛盾

**别追求问全。** 漏掉的细节可以在方案里标"待定"，但用户的耐心是有限资源。

> 反过来也要防：**用户开始不耐烦时，明确告诉他"再问 N 个问题就出方案"。**
> 给一个可预期的终点，比"快问完了"有用得多。
