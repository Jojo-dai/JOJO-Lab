# Build the agent you want most

把一个模糊的「我想要一个能…的 agent」锻造成**能跑起来的东西**。**七个阶段，顺序不能换**：

```
0 找出不可变核心原则 → 1 苏格拉底式追问 → 2 张小龙式反驳（三轮）
   → 3 得出 agent solution → 4 确认后才动手 → 5 落地执行 → 6 反思总结
```

前四个阶段是**把想法逼清楚**，后三个阶段是**把它做出来并留下为什么**。
两边缺一半，这个 skill 就退化成"陪聊"或者"写代码"。

| 阶段 | 产出 | 详细材料 |
|---|---|---|
| 0 找核心原则 | 一句**逐字引用**的话 | 本文件 |
| 1 苏格拉底追问 | 矛盾清单 | [`QUESTION-BANK.md`](QUESTION-BANK.md) |
| 2 张小龙式反驳 | 三轮 + 诚实记账表 | [`STEELMAN.md`](STEELMAN.md) |
| 3 得出 solution | 六节落地方案 | [`PLAN-TEMPLATE.md`](PLAN-TEMPLATE.md) |
| 4 确认后才动手 | 用户明确点头 | 本文件 |
| 5 落地执行 | 能跑的东西 + **思维链留痕** | [`LANDING.md`](LANDING.md) |
| 6 反思总结 | 三问复盘 | [`LANDING.md`](LANDING.md) |

## When to invoke this skill

用户带着一个**还没成形**的 agent / 产品想法来，要的是"帮我把它想清楚**并且**做出来"。

**不要**用于：需求已经明确、只要写代码的任务（那是普通实现任务）；纯咨询不给落地的情况
（用户明说"只想聊聊"时，停在第 3 阶段）。

---

## 三个不可越过的闸门

这三条是整个流程的价值所在。**违反任何一条，这个 skill 就退化成"陪聊 + 写代码"**。

| 闸门 | 规则 | 违反的后果 |
|---|---|---|
| **不动手闸门** | 阶段 0–3 全程**不装依赖、不写实现代码、不部署**。方案给完、用户明确点头，才进阶段 4 | 用户还没想清楚你就开始写，写出来的东西大概率全废；而且他失去了"改主意"的机会 |
| **原话闸门** | 核心原则必须**逐字引用**用户原话，写进方案的显眼位置，并标注"不可变" | 你转述一遍就丢失了精度。后面所有推导都建立在这句话上，转述等于在沙子上盖楼 |
| **记账闸门** | 每一条被你收回的反对意见，都要**公开列表说明为什么收回** | 见阶段 2「诚实记账」——这是整个方法可信度的来源 |

## 阶段 0：找出不可变核心原则

**这一步不产出方案，只产出一句话。**

用户最初说的往往是**手段**（"我想用 LangGraph 做"、"我想本地跑"），不是**目的**。反复问"为什么"，
直到他给出的那句话，**他自己会承认不容让步**。

标志：用户会用这类措辞 —— "这是我的基本核心原则"、"不可变"、"这个不能动"。

> **实战样本**（一个「录音 → 本地存储 → 提炼要点」的产品）：
> 用户原始需求是"做个会议记录工具"。追问多轮后，他给出的是：
>
> > "LLM 基于转成文字后的会议内容，推理判断是会议还是面试，再进行会议要点／面试要点的提炼，
> > **而不是通过两个版本迭代的方式进行实现**。这个版本里就要实现会议纪要／面试要点的输出。"
>
> 注意这句话里有**两件事**：一个功能要求（LLM 判类型 + 双模板），
> 和一个**否定**（不许分两版做）。那个"而不是"往往比正面的要求更关键 ——
> 它排除了你最容易走的那条路。

**拿到之后立刻拆成硬约束**，写回给用户确认：

```
1. LLM 判断类型 —— 由模型读转写文字后推理，不由用户按按钮选择
2. LLM 提炼要点 —— 会议纪要与面试要点，同一版本内都要输出
3. 单版本交付 —— 不搞"先做面试再做会议"的两阶段
```

### 派生后果：找出用户自己没说出来的张力

核心原则常常**推出一个用户还没意识到的后果**。这是本阶段最有价值的动作 ——
把它说出来，给他选项，别替他决定。

> 同一个样本：核心原则里的"成本低、可追溯、可删除、可自我支配"，
> 与"用云 LLM 提炼"存在**直接张力** —— 文字得出本机。
> 方案里没有回避，而是做成**三档可控、粒度到每一次会话**：
>
> | 档位 | 行为 | 适用 |
> |---|---|---|
> | 提炼关闭 | 只出本地逐字稿，**一个字都不出本机** | 敏感会议 |
> | 提炼开启 | **仅转写文本**出本机；音频、录音永不出 | 面试、日常会议 |
> | 一键清空 | 单次会话的音频 + 逐字稿 + LLM 产出三处同删 | 对应"知情 + 删除" |
>
> 关键：**开关粒度到"每一次会话"，不是全局。** 用户今天开、明天关。

**判断标准**：如果你推导出的后果让用户说了"这我没想到，那确实得处理一下" —— 做对了。
如果他只是点头附和，你多半只是复述了他已知的东西。

## 阶段 1：苏格拉底式追问

**目的不是问全，是问出矛盾。**

问法上有一条铁律：**每个问题都指向一个具体的取舍**，不做"你还想要什么功能"这种开放性收集。
开放式收集会让需求表越来越长，而真正的分歧被埋起来。

提问银行见 [`QUESTION-BANK.md`](QUESTION-BANK.md)。核心是六组：

| 组 | 问什么 | 为什么问 |
|---|---|---|
| **边界** | 这个系统**绝不做**什么？ | 否定比肯定更能定义产品。"什么都行"等于没想清楚 |
| **反例** | 什么情况下你会觉得它做错了？ | 逼出隐含的验收标准 |
| **替代** | 不用 agent / 不用 LLM 能不能做？ | 如果脚本能解决，就不该上 agent |
| **成本** | 这个决定错了，代价是什么？ | 区分"可逆"和"不可逆"的决定 |
| **数据** | 数据从哪来、到哪去、谁能看见？ | 隐私与合规的分歧几乎总在这里 |
| **失败** | 它挂了你怎么知道？ | 逼出"绝不静默"这类要求 |

**节奏**：一次问 2–4 个（用 `AskUserQuestion`），不要一口气甩二十个问题。用户答完一轮，
**从答案里找矛盾**，下一轮专攻矛盾点。

**收手信号**：当你发现新问的问题开始得到重复答案 —— 认知地图已经画完了，进阶段 2。

### 反抗信号：用户在夺方向盘

追问过程中如果出现下面这些，**立刻停下来说清楚**，别继续问：

- 用户开始问"这个怎么实现"（他在往实现跑了）
- 用户说"你先做个版本出来看看"（他想用原型代替思考）
- 用户对你的问题给出越来越短、越来越敷衍的回答

正确动作：明确告诉他"再问 N 个问题就出方案"，给一个**可预期的终点**。
无限追问和零追问一样，都是在逃避交付。

## 阶段 2：张小龙式反驳（三轮）

**这不是"唱反调"，是 steelman** —— 构造你的反对意见**最强的版本**，然后看它站不站得住。

反过来做（先立个稻草人再打）毫无价值，用户会立刻发现你在走过场。

### 三轮的分工

| 轮次 | 攻击什么 | 典型话术 |
|---|---|---|
| **第一轮：攻可行性** | "这东西在你这台机器 / 你的时间预算上做不出来" | 拿实测数字说话，不用形容词 |
| **第二轮：攻必要性** | "就算做出来了，你真的会用吗" | 找"做完了但没解决原始问题"的路径 |
| **第三轮：攻后果** | "它做对了，但副作用你受得了吗" | 隐私、维护成本、信任稀释 |

详细打法与话术见 [`STEELMAN.md`](STEELMAN.md)。

### 诚实记账（核心动作）

**每一轮结束后，把被你收回的反对意见列表公开。** 这是整个方法可信度的来源 ——
用户看到你会认输，才会相信你没认输的那些是真问题。

> **实战样本**，收回的两刀：
>
> | 我之前砍的 | 收回理由 |
> |---|---|
> | "LLM 自动判断会议/面试" | 我的反对理由是"猜错了你不知道"。但该失败模式**可被设计掉**：LLM 同时输出判断结果 + 置信度，界面显示并给一个「改成会议／面试」按钮，点了重跑 `structure` 节点。**同版本内解决，无需两版迭代。** |
> | "会议 + 面试不能同时做" | 同一理由。双模板是 `structure` 节点内的分支，不是两个产品。 |
>
> 然后**保留没被说服的那部分**，不粉饰：
>
> > **保留的分歧（不在方案里争论，但你应知道）**：把产品最重要的判断交给概率模型，
> > 长期看会稀释你对它输出的信任。缓解手段已内建（置信度 + 一键纠正 + 保留原始逐字稿）。

**没有"收回"不等于白做。** 一个站得住的反对意见，往往直接变成方案里的一节 ——
上面那条"保留的分歧"就变成了验收清单里的一项。

### 什么样的反驳是无效的

| 无效反驳 | 为什么无效 | 改成 |
|---|---|---|
| "这样可能有问题" | 没有具体失效路径，用户无法据此决策 | "当 X 发生时，会导致 Y，代价是 Z" |
| "业界一般不那么做" | 诉诸惯例，用户可以直接不听 | 给出你这样做的**具体环境约束** |
| 一口气列 20 条反对 | 稀释了真问题，用户只会挑软柿子捏 | 每轮 2–3 条，且**排序**，最硬的那条放第一 |
| 反对完不给替代 | 等于只说"不行"，把难题丢回给用户 | 每条反对**必须**配一个"但可以这样绕过" |

## 阶段 3：得出 agent solution

用 [`PLAN-TEMPLATE.md`](PLAN-TEMPLATE.md) 的骨架。**七节缺一不可**：

1. **用户不可变的核心原则**（逐字引用 + 拆成硬约束）
2. **我收回的反对意见**（诚实记账表）—— 放在前面，不藏在附录
3. **由核心原则推出的新后果**（用户没意识到的张力 + 选项）
4. **架构与节点/模块表**（每个节点写职责 + 断点 / 失败姿态）
5. **里程碑 —— 按"核心原则最早落地"排序**
6. **验证方式 —— 每条断言配一个能失败的检查**
7. **诚实风险 —— 把最大的不确定性写在第一条**

第 5 条最容易做错。**不要按技术依赖排序，要按"用户最在意的东西什么时候能用上"排序。**

> 样本里 M2 结束就实现了全部核心原则，M3（说话人分离）是质量升级而非功能前置。
> 那句"（这也是我原本坚持'M2 就可用'的同一个判断，只是把 LLM 段从 M3 提前到了 M2——
> 因为它是你的核心原则）"—— **明确写出你的排序依据，用户才能在你排错时纠正你。**

第 6 条：每条断言配一个**可执行的检查**，
包括"关掉联网开关 → 断言**网络无任何外发请求**"这种能证伪的写法。
**不能证伪的验证项等于没写。**

第 7 条不许写"可能有一定风险"这种废话。**第一条风险必须是能用数字描述的**：

> 1. **CPU 转写速度是最大不确定性。** 在一台无可用 GPU 的老笔记本上，
>    3 小时音频可能跑 45–90 分钟。M1 的对比测试就是为了量出这个数。
>    太慢的退路：只转写关键窗口 / 换云 ASR（但与"本地"冲突，需你拍板）。

方案给完后 **停下来等确认**。明确告诉用户："你点头我才动手。"

---

## 阶段 4：确认之后才动手

**这是唯一的入口条件：用户明确点头。** 没点头就不进阶段 5，没有例外。

"我看看"、"感觉还行"、"你先写着"都**不算**点头。要的是"开始做"这个意思的明确表达。

点头之后，进 [`LANDING.md`](LANDING.md) 的落地步骤。

---

## 阶段 5：落地执行

**先做实验，不做地基。先保数据，再谈功能。**

这一步的核心不是"把代码写出来"，是**边写边留下为什么** —— 见
[`LANDING.md`](LANDING.md) 的两部分：落地步骤、思维链留痕。

三条最容易违反的纪律：

| 纪律 | 违反的样子 |
|---|---|
| **M1 必须是"最不确定的那件事"** | 先搭目录、先配环境、先做最容易的 —— 把风险留到最后 |
| **一次只改一个变量** | 同时改两处，你得到的是"现在能跑了"，不是"因为什么能跑" |
| **不可再生的数据第一步落盘** | 音频、原始素材、用户手写草稿，早于任何可能失败的步骤 |

---

## 阶段 6：反思总结

跑完必须产出，三问：

| 问 | 要写什么 |
|---|---|
| **哪些反对意见我收回了？** | 复盘诚实记账 —— 收回对了吗？有没有当时该坚持却让步的？ |
| **哪些判断被实测推翻了？** | 我给过的、后来数据打脸的结论。这类最值钱，因为它校准的是你的判断力本身 |
| **还有什么是未知的？** | 不能装的"已知局限" |

详细写法与"怎么把'我觉得'变成'我量过'"的路径见 [`LANDING.md`](LANDING.md)。

## 已知局限（说清楚，不装作没事）

- **本方法来自单一产品线的落地经验**，不是统计结论。苏格拉底式追问在
  **愿意被追问**的用户身上效果最好；面对"你别问了照做就行"的情况，应直接跳到阶段 3，
  但要**明确告知跳过了什么**。
- **阶段 0 有失败模式：用户给不出"不可变"的那一句话。** 那通常意味着他自己还没想清楚，
  此时正确动作是**继续问或建议先别做**，而不是替他编一条然后当成他的原则往下推。
- **阶段 2 的"三轮"是上限不是配额。** 第一轮就被驳倒三条时，继续硬凑三轮会显得在找茬。
  被驳倒就认，认完进方案。
- **诚实记账需要你顶住自我辩护的本能。** 用户能闻出敷衍的收回 ——
  "你说得对，我错了"后面不接**具体的失效机制**，等于没认。
- **本 skill 不覆盖"想法本身是坏的"这种情况。** 如果三轮下来核心原则站不住，
  正确输出是告诉他别做，而不是产出方案。这一条由你判断，skill 不替你决定。
- **阶段 5 的思维链留痕是有成本的。** 记太细会拖慢落地，记太粗等于没记。
  [`LANDING.md`](LANDING.md) 给的是取舍标准，不是"什么都记"。
