## 它解决的痛点

```
开完会不用回忆。录音落地成文字，要点自动提炼出来 —— 而且你随时知道它有多确定。
```

三件事必须同时成立，缺一条产品就不成立：

| 部分 | 要求 | 做砸的后果 |
|---|---|---|
| **录得全** | 线下走麦克风、线上走系统声，**不能丢音频** | 录了三小时的会少了十分钟，而你不知道 |
| **存得住** | 音频、逐字稿、要点**都留在本机** | 一次泄露毁掉整个产品的信任基础 |
| **提炼准且自知** | 给要点的同时给**置信度和依据**，判错了看得见、一键能改 | 结论无法质疑，用户要么盲信要么弃用 |

**第三条是这类产品最容易做砸的地方，也是这个 skill 的重点。**
大多数同类产品只给结论 —— 那等于把"机器判断"包装成了"事实"。

## 置信度：要设计掉的失败模式

用户最不能接受的不是"它做错了"，而是"**它做错了，而我不知道**"。

**三个字段必须同时给：`verdict` + `confidence` + `reason`。**

| 字段 | 作用 | 只有结论会怎样 |
|---|---|---|
| `confidence` | **分流量级**：高了直接看，低了重点核对 | 用户无法分配注意力 |
| `reason` | **可质疑的依据** | 结论不可质疑 = 不可信 |

**而纠正必须只重跑提炼，绝不重跑转写** —— 这是设计能不能成立的关键：

| 步骤 | 耗时量级 | 纠正时 |
|---|---|---|
| 转写 | 分钟级 | **绝不重跑** |
| 提炼 | 秒级 | 只重跑这一步 |

否则"判错了也不要紧"就是空话 —— 用户会为了省时间而忍受错误结论。

> **诚实边界**：模型自报的置信度**不是校准过的概率**。它的价值在**排序**
> （哪个更可疑），不在绝对值。用做**注意力分配**，不要对外宣称"95% 准确率"。

## 里面几个不写下来一定会重踩的

| 场景 | 结论 |
|---|---|
| 线上会议录不到对方声音 | 走的是**系统声通道**（loopback / 虚拟声卡），不是麦克风 |
| 混合录音尾部被截断 | 以**最长的一路**为基准、短的补零，不是对齐到最短 |
| 模型不给时间戳 | 用 **VAD 的语音段边界**当时间戳。但音频**不能整段灌进 VAD**（环形缓冲溢出），样本必须在 `pop()` **之前**读走 |
| 参数怎么定 | 量出来，并把那张表写进文件头。实测中**准确率不是随窗口单调上升的** —— 出现过窗口翻倍反而丢词 |
| 音频掉块 | 光提线程优先级不够，必须**对账告警**，并告诉用户"**时间是错的**" |
| 关窗丢录音 | GUI 必须接管关窗事件。默认行为是主循环退出、录音线程跟着死 —— **录了三小时的会，手滑点个 X 就全没了，且没有任何症状** |
| 中文检索 | FTS5 用 `trigram`。但**两字词查不出来**（trigram 要 3 字符）、`. % -` 会被当语法 |
| 长录音 | 逐字稿超长时要走 MAP→MERGE，**在段边界切**。按字数硬切会让模型**脑补半句话** |

## 落地顺序

```
1. 量硬件：跑 bench，确定最慢的环节和真实耗时     ← 决定产品可不可行
2. 定数据流向：唯一外发通道 + 最小必要集 + 开关粒度
3. 打通录音：两种音源 + 混音 + 电平反馈 + 掉块对账
4. 打通转写：VAD 合成时间戳 + 实测窗口 + 断点续跑
5. 接提炼：单块直路 → 多块 MAP/MERGE
6. 加置信度：三字段输出 + 呈现规则 + 一键纠正
7. 本地检索：中文分词器 + 删除要清干净几处
8. 交付层：启动入口 + 失败时能看懂的错误提示
```

**第 1、2 步不能跳过也不能后置** —— 它们决定的是"要不要做"和"能不能做"。

## 两条跨条目的纪律

1. **一次只改一个变量。** 同时改两处，你得到的是"现在能跑了"，不是"因为什么能跑"。
2. **触发条件依赖输入规模的分支，要专门造样本测。** 短路径天天绿，长路径一进就崩。

## 已知局限

**纯 CPU 转写速度是这类产品的根本瓶颈**（3 小时音频 ≈ 十几分钟）。
如果场景是"开完会立刻要纪要"，这个延迟不可接受 —— 那就该去谈云 ASR，而不是继续优化本地推理。
另外：模型自报置信度**未经校准验证**；说话人分离不在本 skill 范围内；
长录音断点续跑是**设计而非保证**，未在真实长录音上强杀验证过。
