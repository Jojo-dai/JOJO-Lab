# 坑表（按症状查）

做「录音 → 本地存储 → 自动出会议要点」这类 agent 时踩过的坑，**全部实测**，不是推测。

**查法：按你看到的现象找**，不用按分类找。

---

## 按症状速查

| 你看到的现象 | 真因 | 修法 |
|---|---|---|
| `import <推理库>` 直接段错误 | 新版二进制用了老 CPU 不支持的指令 | **先降版本** |
| 加载模型时段错误 | 同上 | 降版本，别绕 |
| `FileNotFoundError` 找不存在的目录（如 `_rocm_sdk_core/bin`） | 某个中间版本的打包 bug | 换到相邻的稳定版本 |
| `No module named 'pkg_resources'` | 新版 setuptools 删了它，而老版库还在 import | 钉 `setuptools<81` |
| 线上会议**录不到对方声音** | 用的是麦克风而不是系统声通道 | 走 loopback / 虚拟声卡 |
| 混合录音**尾部被截断** | 两路音源按较短的一路对齐了 | 以**最长的一路**为基准，短的补零 |
| `data discontinuity` 警告 | 录音线程被饿死，音频缓冲溢出 | 提线程优先级 **+ 必须对账告警** |
| 逐字稿时间戳对不上真实录像 | 音频掉块后所有后续时间点前移 | 报 `captured_ratio`，明确告诉用户"时间是错的" |
| **关掉窗口，录音整段消失** | `mainloop` 退出 → 进程结束 → daemon 线程跟着死 | 接管关窗事件 |
| 关窗后报 `TclError` / 结果被吞掉 | 窗口销毁后 GUI 定时回调不可用 | 加"已关闭"标志，改走控制台输出 |
| VAD 只切出 1 个 0 长度的空段 | 整段音频灌进了环形缓冲区，溢出 | 小块喂 + **边喂边取** |
| VAD 段数正确，但**每段时长都是 0.00s** | 在 `pop()` **之后**才读样本，缓冲已回收 | 先 `.copy()` 再 `pop()` |
| 长音频转写比预期慢很多 | 窗口开太大（注意力是平方复杂度） | 看实测窗口表 |
| 分块转写准确率**反而下降** | 窗口太小，模型看不到足够上下文 | 加大窗口，**别取消分块** |
| 中文两字词搜不到 | FTS5 trigram 至少要 3 个字符 | <3 字退回 `LIKE` |
| `fts5: syntax error near "."` | 查询串里 `. % - "` 被当 FTS5 语法 | 包成短语查询 + 引号翻倍转义 |
| 删了会话还能搜到内容 | 只删了主表，索引没删 | 显式删索引表 |
| 逐字稿超长时流水线崩 | 分段路径没专门测过 | 见下「长输入」 |
| 模型编出没出现过的内容 | MAP 提示词没说"你只看到片段" | system prompt 里写死 |
| 批处理文件报 `'录' 不是内部或外部命令` | 存了 UTF-8，Windows cmd 按 GBK 逐字节解析跑偏 | 存 **GBK** |
| 脚本建的桌面快捷方式**看不见** | shell 不为脚本创建的文件刷新桌面 | 建完通知 shell |
| 自己生成的图标渲染成纯白 | 量纲混用（颜色 0–255、alpha 0–1），末尾又统一乘 255 | **统一量纲** |

## 录音

### 两种音源

| 场景 | 通道 |
|---|---|
| 线下会 | 麦克风 |
| 线上会 | **系统声**（loopback / 虚拟声卡）—— 不是麦克风 |

**每路一个独立线程**，互不阻塞。

**混音规则**：以**最长的一路**为基准，短的补零。截断到最短 = 丢尾部。
多轨混合前先除以轨数，防止叠加削波。

**电平必须暴露给 UI。** 录音最怕静默失败 —— 用户看到电平在跳，才知道真的在录。

### 音频掉块

```
data discontinuity = 录音线程被饿死，音频缓冲溢出，掉的是永久丢失的音频
```

**典型触发场景**：后台正在跑转写，CPU 被占满。

**光提线程优先级不够 —— 必须对账：**

```python
captured_ratio = 实际采到的样本数 / (墙钟时长 × 采样率)
```

`ratio < 0.99` 就告警，并且要说清**后果**：

> ⚠ 录音中间掉了约 N 秒（采到 97%）。**时间是错的**，别按逐字稿的时间去对原始录像。

**「时间戳会前移」这句必须提。** 否则用户会拿逐字稿对录像，
得出"这工具不准"的结论 —— 而真因是音频丢了。

### 关窗丢录音

**默认关窗行为会静默丢掉一切。** 桌面 GUI 的 `mainloop` 直接退出、进程结束，
录音线程是 daemon 跟着一起死 —— 停止和保存的代码根本不会执行。

> 录了三小时的会，手滑点个 X 就全没了，**且没有任何症状**。

处理四件事：

1. 弹确认框，**说清后果**（"关闭会先停止并保存"）
2. 停止 + 保存（**同步**完成）
3. 流水线在后台跑完，进度打到控制台
4. 窗口销毁后定时回调会抛异常 → 加"已关闭"标志**改走打印**，别把结果咽掉

## 转写

### 窗口大小

**准确率不是随窗口单调上升的。** 实测中遇到过"窗口翻倍反而丢词"。

- 太小 → 上下文不足，准确率掉
- 太大 → 耗时陡增（平方复杂度），收益不稳
- 整段 → 最准，但长录音根本不可行

**必须扫一遍定参数，并把实测表写进文件头**，注明"别凭感觉改"。

> **一个推导过程的教训**：曾断言"分块能提升准确率"，实测发现第一版分块**比整段还差**。
> 排除法走了一遍 —— 先排除上下文假设（窗口合并后仍一致）→ 再排除随机性（连跑三次相同）
> → 最后做剂量-反应测试，证明准确率**随窗口单调上升**。
> 结论修正为"分块确实有代价，只是被窗口大小掩盖了"。
>
> **断言错了不可怕，可怕的是用一个新断言去覆盖旧断言。**
> 排除法 + 剂量-反应，才是把"我觉得"变成"我量过"的路径。

### 用 VAD 合成时间戳

```
音频 → VAD 找语音段 → 在静音边界合并成固定长度窗口 → 每个窗口单独送 ASR
```

**块的边界即时间戳。** 静音处切断，天然不切碎句子。

白拿三个好处：静音不送模型（省时间）、每块是天然进度单位（可断点续跑）、内存可控。

| 坑 | 现象 | 修法 |
|---|---|---|
| 整段灌入 | 环形缓冲溢出。实测整段灌入 → **只切出 1 个 0 长度空段** | 小块喂，**边喂边取** |
| 读样本太晚 | 段数对，**时长全是 0.00s** | `.copy()` 必须在 `pop()` **之前** |
| 最大段长限制不生效 | 实测拿到过超出限制的段 | 在合并函数里加硬切保险 |

> 第二、三条是同一类问题：**库的"应该"和实际行为有差距时，要有自己的兜底校验。**
> "检查每段时长 > 0"这一行不写，bug 会一路带到生产，表现为所有时间戳都是 00:00。

## 本地存储

**唯一外发通道**：所有外发调用收进一个模块，其他地方不许直接发请求。
**「数据有没有出本机」因此变成可审计的问题** —— 查一个文件就能回答。

**最小必要集**：典型答案是「音频永不出本机，只有转写文字可以出」。
这个拆解把二选一变成三档可控（提炼关闭 / 仅文字外发 / 一键清空）。

**粒度**：开关必须到**每一次会话**，不是全局。
全局开关是"一次决定"，遇到敏感的那一场用户只能不用这个工具。

**验证（能证伪）**：关掉开关跑一次 → **断言网络无任何外发请求**。

**删除要清干净几处**：典型四处 —— 音频、逐字稿、要点、索引。
少一处就是留尾巴，用户以为删了其实还能搜出来。

## 置信度与纠错

**要设计掉的失败模式**：不是"它做错了"，而是"**它做错了而我不知道**"。

只输出结论 = 把概率判断包装成事实。用户只能盲信或全量人工核对。

**三个字段必须同时给**：`verdict` + `confidence` + `reason`。
只有结论没有依据 = 要求盲信。

**呈现**：置信度放在结论旁边（不折叠）、低于阈值显式提示核对、依据必须可见、
**永远给一个纠正按钮**。

**纠正只能重跑提炼，绝不重跑转写** —— 这是设计能不能成立的关键：

| 步骤 | 耗时量级 | 纠正时 |
|---|---|---|
| 转写 | 分钟级 | **绝不重跑** |
| 提炼 | 秒级 | 只重跑这一步 |

把流水线中间状态持久化，纠正时从对应节点重新开始。
否则"判错了也不要紧"是空话 —— 用户会为了省时间而忍受错误结论。

**诚实边界**：模型自报的置信度**不是校准过的概率**。
它的价值在**排序**（哪个更可疑），不在绝对值。用做**注意力分配**，不要当成准确率承诺。

## 长输入

```
≤ N 字 → 一次调用
> N 字 → MAP（分段提事实）→ MERGE（合并成要点）
```

| 坑 | 修法 |
|---|---|
| **按字数硬切** | 必须在**段边界**切。硬切把句子劈两半，模型读到半句会**脑补后半句**，脑补内容混进结果 |
| 丢失时间信息 | 每组带**自己的起止时间**，MAP 提示词里的"约第 N 分钟"来自这里 |
| **模型在片段里找"整场主题"** | MAP 的 system prompt 写死："你**只**会读到**一个片段**（不是全部）" |
| 分段路径没测过 | **长路径必须单独测。** 只要一条分支的触发条件依赖输入规模，就要专门造够大的样本 |

## 绝不静默

| 失败模式 | 危险度 | 处理 |
|---|---|---|
| 崩溃 | 低（会被发现） | 记 `errors` |
| 明确报错 | 低 | 记 `errors` |
| **判断失败后硬套模板** | **高** | **不许**。跳过提炼，只交逐字稿，标 `partial` |
| **模型脑补未出现的内容** | **高** | 提示词写死"原文没有的不编，标未提及" |

**「没有就写无」这一句必须写。** 不写的话，模型面对空集默认会编一个像样的。

**用户身份决定输出内容**，不只是措辞。同一个录音：参会者要决议和待办，
汇报者要"我哪里没讲清楚"，被评估方要"我哪几句答短了"（且**只要事实，不要评价**）。
**先确定使用者是谁，再写模板。**

## 环境

**原生推理扩展一加载就段错误时，排查顺序：**

```
1. 降版本  ← 绝大多数问题在这一步解决
2. 查 setuptools（老版本可能还要 pkg_resources，新版已删除）
3. 最后才查 DLL / 驱动 / VC++ 运行库
```

不要一开始就去翻 DLL、查 CPU 厂商 —— 那是最后一步，也最浪费时间。

**把根因写进依赖清单注释，并且写行动指令：**

```
# >>> 换机器若报段错误，先怀疑这几条版本，不要先去查 CPU 厂商。<<<
```

写"为什么钉这个版本"不够，要写到让下一个人知道**下次遇到同样症状先做什么**。

## 交付层

| 坑 | 现象 | 修法 |
|---|---|---|
| **批处理文件存 UTF-8** | cmd 按 GBK 逐字节解析 → 中文的**字节碎片被当命令执行**。文件头的 `chcp 65001` 救不了 | 存 **GBK** |
| 快捷方式不显示 | shell 不为脚本创建的文件刷新 | 建完通知 shell |
| 桌面是唯一入口太脆 | 被盖住 / 拖走 / 多显示器跑丢 | **开始菜单也放一份** |
| 图标渲染成纯白 | 颜色 0–255、alpha 0–1，末尾又统一乘 255 | **统一量纲** |

> **量纲那条的规律**：图像管线里混用量纲，错误会以"看起来完全无关"的方式表现出来
> （形状对、颜色全错）。要么全 0–1，要么全 0–255，**别混**。

## 附：四条跨条目通用纪律

1. **一次只改一个变量。** 同时改两处，你得到的是"现在能跑了"，不是"因为什么能跑"。
2. **触发条件依赖输入规模的分支，要专门造样本测。** 短路径天天绿，长路径一进就崩。
3. **把根因和行动指令一起写进代码注释。** "段错误"不是根因，
   "新二进制用了这颗 CPU 不支持的指令"才是 —— 区别在于前者无法据此做决定。
4. **不可再生的数据在第一步就落盘**，早于任何可能失败的步骤。
   音频和原始素材丢一次就永远没了。
